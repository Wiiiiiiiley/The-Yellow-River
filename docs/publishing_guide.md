# 个人网站展示与发布指引

展示入口是项目里的 `website/index.html`。页面使用预先导出的模型结果，提供六河流选择、6小时预测、模型比较和黄河—密西西比河比较学习内容。静态页面不需要后端推理服务；访客看到的数值是已保存的实验快照。

## 本地查看

先在项目根目录运行实验，确认 `experiments/multi_river/` 已有输出，然后启动本地HTTP服务：

```bash
python3 scripts/run_multi_river.py --epochs 25 --hours 8760 --seed 42 --transfer-seeds 42,43,44
python3 -m http.server 8080
```

浏览器访问 [http://localhost:8080/website/index.html](http://localhost:8080/website/index.html)。页面从本地JavaScript资源读取结果快照，因此也支持直接双击 `website/index.html` 查看；HTTP服务便于检查正式发布的目录结构和下载路径。

轻量多河流模块需要Python 3.10或更高版本，以及NumPy、PyTorch；不依赖pandas或torch-geometric。用已安装这些包的环境执行脚本。训练结果改变后，重新运行 `run_multi_river.py` 会生成新的页面数据和报告；`export_river_site.py` 只打包已生成结果，不重新训练或计算指标。只修改页面文字不会重新训练模型。

## 站点与下载材料一起发布

页面中的下载链接可能指向项目内的模型、CSV、协议和研究文档。保留目录层级最直接的方式是把所需文件与 `website/` 一起放在发布根目录，例如访问 `/website/index.html`。若服务器仅允许单一站点目录，先打包成独立发布目录：

```bash
python3 scripts/export_river_site.py --output public_river_lab
python3 -m http.server 8080 --directory public_river_lab
```

随后访问 [http://localhost:8080/](http://localhost:8080/)。把 `public_river_lab/` 的内容作为静态发布根即可，具体选项见 `python3 scripts/export_river_site.py --help`。该目录保留页面所需的实验与文档下载；不能只移动HTML而遗漏这些材料。

训练检查点、原始数据和实验归档可以很大。发布时可以保留模型说明与必要的CSV示例，把较大检查点作为独立可下载附件；链接必须指向实际可访问文件。对真实资料，先确认数据许可与可公开范围。源数据中的身份信息、账户信息和服务密钥不属于展示材料。

发布后检查首页、六条河的切换、三类预测变量、各模型指标、双向迁移结果、出处链接和下载链接。在手机窗口检查图表是否可读，刷新子路径是否能打开；更换静态根目录时尤其要复核相对链接。网页的实验参数与日期应与同一批CSV和JSON一致。

## 适合公开的文字

建议在首页摘要、预测图和指标附近保留“合成数据研究演示”标识，并把模型名称写成“物理引导图时序模型”。标明输入24小时、预测6小时、五个示意节点，说明示例断面与参数未经真实测站校准。出处资料解释河流背景，不验证模型精度。

可以写“训练了六河流模型并进行了留出测试”“在同一合成场景中比较物理软约束与同架构纯数据版本”“完成黄河与密西西比河的双向迁移实验”。性能变化须引用生成结果，包含目标河、变量、预测时长和基线。未完成真实观测验证时，不应把合成指标写成真实洪水预测准确率，也不应把Manning惩罚称作完整PDE求解或已证明的守恒能力。

网站呈现的三个种子差异是训练随机性分析。预测范围另由验证集绝对残差的90%分位数计算，应标为“90%经验误差区间”并同时展示测试覆盖率；它不保证未来覆盖，也不等同于洪水风险置信区间。预报起点是输入文件的末时刻，并非实时更新。需要实时预报时，还须另外实现真实输入更新、时间戳和质量检查、在线推理，以及独立观测验证。

本次交付准备的是本地可展示与可发布的文件。选择域名和托管位置后，可将发布目录交给静态网站托管服务；当前文件的生成不等于已经对外上线。
